# Веб-панель (`dockrunner`)

React + Vite + MUI. Без бэкенда работает на моках — можно смотреть и кликать.

## Запуск

```bash
cd dockrunner
npm install
npm run dev
```

Адрес API задаётся в `.env`: `VITE_API_URL=http://localhost:8080` (по умолчанию тот же localhost:8080).

## Страницы

- **Статистика** — ресурсы за 14 дней, карта серверов, последние события, лимиты профиля.
- **Приложения** — список, создание только из Git: ссылка на репозиторий → проверка на воркере (клон в папку пользователя, поиск Dockerfile/compose в корне) → сборка и запуск. Детали: обзор, логи, параметры запуска с выбором env-конфига.- **Домены** — привязка домена к приложению и воркеру, Caddy выпускает HTTPS.
- **Конфигурации .env** — до 10 наборов переменных на пользователя.
- **Базы данных** — PostgreSQL, Redis, MongoDB, SQLite. Данные подключения видны только после создания пользователя; удалить/изменить его нельзя. Лимит — по занятому месту (см. ниже).
- **Файлы** — папки и файлы в личной директории на воркерах: создание папок, загрузка с заменой, скачивание, удаление файлов и папок целиком (с подтверждением). Дальше своей папки выйти нельзя.
- **Уведомления** — системные события, отметки о прочтении.
- **Администрирование** — пользователи (создание, блокировка, тариф + срок), чужие контейнеры (старт/стоп/рестарт), серверы (перезагрузка, heartbeat, пинг). Работает через реальный API бэкенда, пункт меню виден только роли `admin`.
- Карта серверов показывает последний heartbeat и пинг от клиента до агента (`/health` агента).
- **Персонализация** — тема, фон. **Профиль** — пользователь, тариф и занятое место (контейнеры + файлы).

## Вход

Логин идёт в бэкенд (`POST /api/v1/auth/login`), токены хранятся локально, сессия восстанавливается через `GET /auth/me`. Демо-прифилла нет — нужны реальные данные из базы.

## API-слой (`src/api/`)

Все запросы — только через `src/api/`, по страницам не разбросаны:

| Файл | За что отвечает |
|---|---|
| `client.ts` | базовый `fetch`: URL, Bearer-токен, ошибки |
| `auth.ts`, `users.ts`, `nodes.ts` | совпадают с реализованными роутами бэкенда |
| `applications.ts`, `containers.ts`, `domains.ts`, `envConfigs.ts`, `volumes.ts`, `notifications.ts`, `overview.ts` | контракты под будущие модули бэкенда |
| `containers.ts` | Запуск в стиле docker run: check → опрос → run, refresh |
| `files.ts`, `storage.ts` | Файлы пользователя на воркерах; занятое место |
| `databases.ts` | мок-провайдер до появления бэкенд-модуля |

Общие константы: версия — `src/config/appConfig.ts`, тариф — `src/config/tariff.ts`, приложения — `src/config/applications.ts`.

## Что уже на реальных данных, а что на моках

Реально ходят в API: вход, админка, файлы, место в профиле, карта и выборы серверов (`GET /agents`), список приложений и логи/параметры деталей (`GET /containers/mine`, `.../:id/logs`, `.../:id/spec`), создание (check/run) и кнопки обновления, тома, env-конфиги, статистика дашборда (карточки, график ресурсов из InfluxDB, место, активность), лимиты профиля и портов (`GET /quotas`, реальные пробросы из таблицы).
На моках пока: домены, уведомления — под них ещё нет модулей бэкенда.

## Тариф «Студенческий» и лимиты

Приложений — 10, доменов — 5, портов — 5, env-конфигов — 10, места под базы данных — 10 ГБ. Лимит баз считается суммой занятых гигабайтов, а не числом баз.
